# Phase 21 — UI Design Contract

> Visual and interaction contract for visible browser supervision, local
> dashboard pairing, view-first remote access, and one-controller remote
> control. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## Product and Surface Boundary

Phase 21 turns the existing supervision placeholders into live,
browser-authoritative UI. It extends three established surfaces without adding
a new application shell:

| Surface | Role | Phase 21 contract |
|---------|------|-------------------|
| Native Chromium chrome and tab badge | Always-visible compact state | Show tab ownership/agent activity, trusted viewers, controller state, active remote action, and health without exposing codes or opaque identities. |
| Prometheus side panel | Immediate in-context control | Show the selected tab's viewer/controller state, current safe action category, and a one-step `Stop control` affordance whenever remote control is active. |
| Control Panel `Supervision & Pairing` section | Dense lifecycle surface | Select an eligible target, create/copy one-time pairing codes, inspect viewers and the sole controller, enable or revoke access, inspect stream/resync state, and read metadata-only audit activity. |
| Browser-owned Views dialogs | Security-sensitive foreground decisions | Confirm control enablement and consequential remote actions. Preserve the existing native-only vault confirmation flow. |

The side panel remains exactly four modes: `FSB Agent`, `Explorer`, `Tabs`, and
`Tools`. Supervision is a persistent status strip within the existing panel,
not a fifth mode. The Control Panel retains its nine-section order; Phase 21
replaces only the `Supervision & Pairing` placeholder and the corresponding
read-only permission/diagnostic status.

This phase does not add a hosted dashboard, LAN discovery, public listener,
cloud relay, QR-code service, video feed, screenshot loop, terminal, bundled
agent client, or extension-page policy. There is no `Open dashboard` or
`Connect over network` action. Pairing serves an already-running local client
through the existing authenticated loopback gateway.

### Locked trust model

- Pairing is regular-profile-only and local-first.
- Every redeemed dashboard begins `View only`.
- Control is granted only by a fresh local `Enable control` decision for the
  exact pairing and tab.
- A tab may have several independent viewers and exactly one controller.
- The browser remains authoritative for profile, window, tab, owner, document,
  stream sequence, controller, expiry, revocation, and every action decision.
- Expiry, revocation, ownership loss, target close, profile shutdown, or
  `Stop control` invalidates control immediately. The UI never depicts a grace
  period after native authority is gone.

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing Prometheus Chromium Views and packaged WebUI; no additional design-system tool |
| Preset | Not applicable |
| Native components | Existing tab-status badge, Chromium Views labels/buttons/dialogs, and Prometheus semantic action resolver |
| WebUI components | Dependency-free HTML/CSS/minimal JavaScript backed by browser-process handlers and sanitized snapshots |
| Icon library | Existing packaged Font Awesome Free subset through `PrometheusAction` and GRIT resources only |
| Font | Packaged Poppins for the surface title/code emphasis, packaged Space Mono for code/time/metadata, system UI for body and controls |
| Radius | 8px maximum; a pill is allowed only for compact status/provenance chips |
| Remote resources | None |

React, Next.js, Vite, shadcn, external component registries, remote fonts,
remote icons, external stylesheets, and third-party UI blocks must not be added.
The current implementation is native Chromium Views plus packaged WebUI, so the
shadcn initialization gate is not applicable.

### Visual character

The UI is a calm local-control surface, not a marketing dashboard. Use flat
lists, compact summaries, hairline separators, and one purposeful pairing-code
panel. Do not use nested cards, decorative gradients, glowing connection maps,
large counters, avatars, ornamental client illustrations, or color-coded
charts. The most important object changes by state:

- idle: `Create pairing code`;
- pending: the one-time code and expiry;
- paired view-only: connected viewers and `Enable control`;
- controlled: controller identity, current action, and `Stop control`;
- stale/error: the truthful state and its single recovery action.

## Spacing and Stable Dimensions

These are the only spacing values permitted for new or touched Phase 21
margin, padding, gap, and inset rules:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label and compact inline gaps |
| sm | 8px | Status-chip internals, adjacent compact controls, row-cell gaps |
| md | 16px | Side-panel/status-strip padding, list gaps, form groups |
| lg | 24px | Control-panel section and dialog padding |
| xl | 32px | Major pane separation and stable non-interactive row height |
| 2xl | 48px | Minimum interactive hit target, header and summary rows |
| 3xl | 64px | Major empty-state separation only |

Exceptions: none. Icon sizes, font sizes, border widths, and responsive
breakpoints are dimensions rather than spacing exceptions.

Stable dimensions:

- native tab-state icons: 12px, with 4px gaps;
- WebUI/native icon-only controls: 32px visual icon area inside a 48px minimum
  hit target;
- selectable rows, buttons, inputs, target selector, and client actions: 48px
  minimum;
- passive audit rows: 32px minimum, expanding vertically for wrapped copy;
- pairing-code presentation: 48px minimum line box with no width change while
  the countdown updates;
- side-panel supervision strip: intrinsic height, never overlaying panel mode
  content or the task composer;
- state changes must not shift the target selector, code actions, client-row
  controls, or side-panel stop action.

## Typography

All Phase 21-authored UI uses exactly four font sizes and exactly two weights.
No other font size or weight may be introduced in touched selectors or native
styles.

| Role | Family | Size | Weight | Line Height | Usage |
|------|--------|------|--------|-------------|-------|
| Metadata | Space Mono / system monospace | 12px | 400 | 16px | Pairing code support text, countdowns, timestamps, typed states, safe origin metadata |
| Body | system UI | 13px | 400 | 20px | Descriptions, client rows, activity, errors, dialog body copy |
| Heading | system UI | 16px | 800 | 20px | Section groups, client/target titles, dialog titles |
| Display | Poppins / system fallback | 20px | 800 | 24px | Control-panel title and the pairing code only |

Buttons, selected navigation, state labels, and tab-badge tooltips use the
appropriate 12px or 13px role at weight 800. Pairing codes use Space Mono at
20px/800 with tabular characters. Letter spacing is zero; uppercase code
characters do not justify wide tracking.

## Color and Theme Contract

The composition follows the established warm 60/30/10 system in dark and
light themes.

| Role | Dark | Light | Usage |
|------|------|-------|-------|
| Dominant (60%) | `#141110` | `#fffdfb` | Page/panel background and calm unframed content |
| Secondary (30%) | `#1d1816` | `#f3ede6` | Section rail, pairing panel, rows, inputs, dialogs |
| Accent (10%) | `#ff6b35` | `#ff6b35` | Reserved elements below only |
| App backdrop | `#0d0a09` | `#e9e2da` | Browser/window backdrop outside the product surface |
| Tertiary surface | `#26201d` | `#f1ebe4` | Hover/selected row and bounded empty-state region |
| Primary text | `#f6efe9` | `#1f1a17` | Main readable text |
| Secondary text | `#d2c1b4` | `#6a584d` | Supporting descriptions |
| Muted text | `#a99283` | `#8d7a6e` | Inactive metadata, ended sessions, timestamps |
| Healthy | `#2f9e7e` | `#2f9e7e` | Connected/view-only/live states in bounded chips only |
| Warning | `#d29b36` | `#9a6a1e` | Expiring soon, resyncing, and confirmation-needed states only |
| Destructive | `#ff6666` | `#a65b5b` | Revoke/end controls and blocking failures only |

Accent is reserved for:

- the enabled `Create pairing code` primary action;
- active-agent, active-supervision, controller, and active-remote-action glyphs;
- the selected side-panel mode and selected Control Panel section marker;
- visible keyboard focus rings;
- the one-time code's narrow emphasis rule, not its entire background;
- PM/FSB brand treatment.

Accent must not fill the entire supervision section, every viewer row, every
status chip, every timer, every copy button, or every secondary action. A
controller is not an error and must not use destructive red. Color never carries
state alone; every color state has visible or accessible text.

### Dark, light, and Private states

- Dark and light are token swaps. Geometry, icon size, border width, and row
  height remain byte-for-byte equivalent across themes.
- Text targets 4.5:1 contrast; focus and non-text state indicators target 3:1.
- Private windows never inherit regular-profile pairing data. Native badges and
  the side-panel supervision strip stay absent. If the Control Panel shell is
  reachable, the section renders only `Unavailable in Private` and `Pairing and
  remote control are disabled in Private windows.` with the muted
  `PrometheusAction::kUserSecret` icon.
- Private state uses secondary/muted tokens, not accent or destructive color.
  It has no target picker, pairing code, viewer count, controller label, or
  action button.

## Browser-Owned UI Data Contract

Renderer-visible state is a sanitized projection of a fresh browser-owned
snapshot. The WebUI may render only:

- a bounded safe target title and canonical origin without path, query,
  fragment, credentials, or profile path;
- target availability and current owner/active-agent safe labels;
- bounded trusted-client display labels, with `Local dashboard` as fallback;
- viewer count, `View only`/`Controller`, safe connected/last-seen times, and
  remaining expiry;
- stream state (`Live`, `Resyncing`, `Paused`, `Ended`) and a closed remote
  action category/state;
- recent metadata-only audit events and typed failure codes;
- the one-time pairing code only in the direct successful response to the
  intentional create-code action.

The regular observer snapshot must structurally exclude pairing codes,
dashboard session IDs, controller lease IDs, owner/session authority IDs,
gateway tokens, browser/profile paths, document tokens, raw stream epochs,
selectors, DOM content, typed values, page text, prompt text, secret values,
authorization material, and request/response bodies. Empty strings, CSS hiding,
or masking are not substitutes for structural exclusion.

WebUI messages express intent only. A selected target row comes from the latest
browser-owned list and is re-resolved by the bound handler; the renderer cannot
assert profile, Browser, tab, owner, document, session, controller, sequence, or
epoch identity. Refresh or observer updates replace state from the browser and
never merge caller-provided identity into it.

### Trusted-client label treatment

- Render a browser-sanitized printable label of at most one line, falling back
  to `Local dashboard`.
- Duplicate labels receive a display-only ordinal such as `Local dashboard 2`;
  never append an opaque session prefix.
- Do not render IP addresses, ports, machine paths, bearer fragments, or raw
  client-provided markup.
- Long labels ellipsize visually and expose only the same sanitized full label
  through the accessible name or tooltip.

## Native Chrome and Tab Badge Contract

The existing non-interactive native tab-status cluster remains the compact
source of truth. It adds no menu and cannot grant or revoke access.

### Visual slots

Use at most three 12px slots so compact tabs do not widen unpredictably:

| Slot | State | Icon and treatment | Accessible phrase |
|------|-------|--------------------|-------------------|
| Owner/agent | Owned but idle | `kBolt`, secondary text | `Owned by {agent}` |
| Owner/agent | Agent active | `kBolt`, accent | `Agent is working in this tab` |
| Supervision | One or more view-only clients | `kEye`, accent | `Supervised by {n} trusted client(s)` |
| Supervision | Controller enabled, no action active | `kShield`, accent | `Remote control enabled for {client}` |
| Supervision | Remote action active | `kCircleNodes`, accent on accent-soft 16px state tile | `Remote action active: {safe category}` |
| Health | Needs attention | `kTriangleExclamation`, warning/destructive as native severity dictates | `Tab needs attention` |

The supervision slot is mutually exclusive by priority: active action,
controller, then view-only. Viewer count and controller identity remain in the
full accessible name even when the compact glyph changes. The safe-default
cluster remains hidden.

The complete accessible name joins every true state in this order:
`Owned by {agent}; Agent is working in this tab; Supervised by {n} trusted
clients; Remote control enabled for {client}; Remote action active: {category};
Tab health OK`. Omit false clauses and use `No agent owns this tab` only when no
owner exists. Never include a pairing code, session ID, origin path, selector,
or typed value.

At severe tab compression, preserve supervision first, active-agent state
second, health warning third, and idle ownership last. The accessible name
still includes all state. Badge changes
must not change tab height, active-address geometry, or close-button
reachability. No pulsing animation is required; active state is a steady icon
and state tile, which also satisfies reduced-motion users.

## Side-Panel Supervision Contract

When the selected tab is supervised, insert a persistent supervision strip
immediately below the four-mode navigation and above the active mode panel. It
remains visible in all four modes. When the selected tab has no viewers and no
controller, remove the strip without leaving an empty container.

### Required content

The strip renders, in order:

1. `Supervised` plus `{n} viewer` or `{n} viewers`;
2. `View only` or `Controlled by {client}`;
3. one current activity line;
4. `Stop control` whenever a controller lease is active;
5. `End supervision` whenever one or more viewers exist;
6. a secondary `Manage access` action that opens/focuses the Control Panel's
   `Supervision & Pairing` section for this browser window.

Current activity uses closed, content-free copy only:

| Native state | Exact visible copy |
|--------------|--------------------|
| View-only stream live | `Viewing current page` |
| Controller idle | `Remote control ready` |
| Validating action | `Validating remote action` |
| Action executing | `Remote action: {Click / Type / Key press / Scroll / Hover / Select / Clear / Drag / Drop / Navigate}` |
| Consequential action paused | `Confirmation required in Prometheus` |
| Navigation/new epoch | `Resyncing supervised view` |
| Sequence gap/backpressure | `View paused for resync` |
| Action blocked | `Remote action blocked` |
| Authority ending | `Stopping control` |

Do not interpolate target text, input values, selectors, page snippets, URLs,
or remote-supplied reason strings into the activity line.

`Stop control` is an immediate safety action, not a confirmation-gated
destructive action. On activation, disable it and show `Stopping control` until
the fresh native snapshot reports `View only` or ended access. It does not undo
an action already completed, but all queued/late action requests must fail fresh
authority validation. Focus remains on the same control location and then moves
to `Manage access` when `Stop control` is removed.

`End supervision` is the immediately reachable stop for view-only as well as
controlled sessions. It opens the exact bulk-end confirmation, then revokes
every viewer/controller for this selected tab; it never affects another tab.

At the 320px target width the strip is one column, all copy wraps, and all
actions are 48px high and full width. It never overlays the task composer or
shrinks another control below its hit target.

## Control Panel Information Architecture

The `Supervision & Pairing` section is ordered for the operator's current
decision, not for implementation internals:

1. section heading and live summary;
2. target selection and pairing creation;
3. one-time code presentation when pending;
4. selected target's stream/current-action state;
5. connected dashboards, controller first;
6. recently ended access;
7. recent metadata-only supervision activity.

The section header shows these browser-owned summaries:

- `Supervision: Off`, `Supervision: {n} viewing`, or `Supervision: Controlled`;
- `Agent: {label}` or `Agent: None`;
- `Controller: {label}` or `Controller: None`;
- `Stream: Live`, `Stream: Resyncing`, `Stream: Paused`, or `Stream: Ended`.

The existing Control Panel header adds one compact global status chip:
`Supervision: {active viewer count}` or `Supervision: Off`. The Permissions
section replaces `Supervision pairing — Not ready` with the read-only invariant
`Supervision pairing — Available locally` and helper copy `View only by default.
Control requires approval in Prometheus.` It is not an editable toggle.

### Target selection

- Label the browser-owned selector `Target tab`.
- Default to the latest eligible page tab in the exact bound Browser, not to a
  tab in another window or profile.
- Rows show sanitized title plus canonical origin. The Control Panel tab,
  secret dialogs, and any surface rejected by current supervision policy are
  unavailable and cannot be selected.
- A browser refresh may update the list, but it must preserve the same selected
  live tab when still eligible. It never silently selects a replacement after
  target loss.
- If none is eligible, disable pairing creation and show `No eligible target
  tab` plus `Open a supported page in this window, then try again.`
- A stale selection fails with `This tab is no longer available. Choose another
  tab and create a new pairing code.` No code is created.

## One-Time Pairing Code Contract

### Creation

The primary idle action is `Create pairing code`. It creates view-only access
for the currently selected exact target. A compact invariant row above it reads
`Access: View only · Expires in 5 minutes · Local connection only`.

Use a five-minute code lifetime as the Phase 21 UI default. A code is eight
uppercase characters from an ambiguity-safe alphabet, displayed as
`XXXX-XXXX`. The hyphen is presentation only. One unredeemed code may be active
for a selected target. Creating another code for that target requires the
replacement confirmation defined below and invalidates the previous code
before the new value is shown.

During creation, retain the target row and replace the action label with
`Creating pairing code`; disable duplicate submission. Browser rejection
restores the action and shows the typed recovery copy.

### Presentation and copy

On success, move focus to a heading `Pairing code ready`, followed by:

- the code in Space Mono 20px/800;
- `Enter this one-time code in the local dashboard. It can be used once.`;
- a timer `Expires in 04:59` using tabular numbers;
- `Copy code`;
- `Cancel code`.

The code is shown only in this intentional panel and is never placed in the
page URL, title, history, console, status chip, tab label, tooltip, diagnostic,
audit event, regular observer snapshot, or MCP response. Mark the code region
as sensitive for internal-surface adapters so generic page reads, structured
supervision, automation snapshots, and diagnostics exports structurally omit
it.

The code is presented once. Successful redemption, expiry, cancellation,
target loss, profile/window loss, or Control Panel reload removes its characters
from the DOM and invalidates it. It cannot be revealed again; the operator must
create a new code. Section changes within the same live Control Panel may
preserve the still-valid code, but must not copy or announce it automatically.

`Copy code` is the only clipboard action. Success announces `Code copied. It
expires in {remaining time}.` through a polite status region without repeating
the code. Copy failure shows `Prometheus could not copy the code. Select it and
copy it manually.` The timer is not live-announced every second; announce only
`Pairing code expires in one minute`, `Pairing code expires in ten seconds`, and
expiry.

On redemption, immediately clear the code and show `Pairing code used` plus
`The dashboard is connected in view-only mode.` The operator may choose `Create
another code` for an additional independent viewer.

### Pending-code states

| State | Heading | Body / recovery |
|-------|---------|-----------------|
| Loading | `Creating pairing code` | `Prometheus is validating the target and local gateway.` |
| Active | `Pairing code ready` | `Enter this one-time code in the local dashboard. It can be used once.` |
| Expiring | `Pairing code expires soon` | `Use this code now or create a new one after it expires.` |
| Redeemed | `Pairing code used` | `The dashboard is connected in view-only mode.` |
| Expired | `Pairing code expired` | `Create a new code to continue.` |
| Cancelled | `Pairing code cancelled` | `The code can no longer be used.` |
| Target lost | `Target unavailable` | `Choose another tab and create a new pairing code.` |
| Create failure | `Pairing code could not be created` | `Check supervision diagnostics, then try again.` |

## Connected Dashboards and Controller Contract

### Summary and ordering

The selected target summary reads one of:

- `No dashboards connected`;
- `1 viewer · View only`;
- `{n} viewers · View only`;
- `{n} viewers · Controlled by {client}`.

Order connected rows with the controller first, then sessions expiring soon,
then most recently connected. Every row shows:

- sanitized client label;
- `View only` or `Controller`;
- `Connected {relative time}`;
- `Expires in {time}`;
- `Last seen {relative time}`;
- its available actions.

Do not show a dashboard session ID, pairing code, IP/port, token fragment,
browser/profile path, document identity, raw sequence, or page content.

### View-only row

Actions are `Enable control` and `Revoke access`. When no controller exists,
`Enable control` opens the native confirmation. When another controller exists,
it is disabled from the current snapshot with helper text `Control is already
enabled for {client}. Stop it before choosing another controller.` A race still
returns the same typed conflict; the UI never replaces the current controller.

### Controller row

Actions are `Stop control` and `Revoke access`. `Stop control` is immediate and
returns the still-valid session to `View only`; it does not end viewing.
`Revoke access` ends both viewing and control for that session after the
confirmation below.

### Multiple viewers and bulk end

Multiple view-only rows remain independent. Expiry or revocation of one row
must not visually change another row. `End all supervision` is a section-level
destructive action shown only when at least one viewer exists. It uses the
confirmation below and revokes every viewer/controller for the selected tab.
It does not affect another tab's sessions.

When a session expires or is revoked, move it out of the connected list and
into a bounded `Recent access` list with `Expired`, `Revoked`, `Target closed`,
or `Authority lost`. Terminal rows have no control actions. Empty recent-state
copy is `No recently ended access.`

## Control Enablement and Confirmation Contract

### Native `Enable control` dialog

Granting mutation authority is a browser-owned Views flow, never a renderer-only
toggle or optimistic state change.

- title: `Enable remote control?`;
- body: `{client} can act in {tab} until {time}. Prometheus will still enforce
  tab ownership, permissions, target validation, and confirmations.`;
- read-only rows: `Client`, `Target tab`, `Site origin`, `Access: Page actions`,
  `Expires`, `Vault: Confirmation required`;
- primary action: `Enable control`;
- safe action: `Keep view only`;
- initial focus: `Keep view only`;
- `Escape`: `Keep view only`;
- no `Always allow`, remember, extension, background bypass, or vault bypass
  choice.

After approval, disable both actions as `Enabling control` until exact target,
owner, permission, pairing, expiry, and controller availability are revalidated.
The row becomes `Controller` only after browser confirmation. Failure leaves it
`View only` and returns focus to `Enable control` with a typed recovery message.

### Consequential remote action dialog

Existing policy decides which remote actions require foreground confirmation.
When required, use a browser-owned Views dialog:

- title: `Confirm remote action`;
- body: `{client} wants to {safe action category} in {tab}. Prometheus will
  recheck ownership, permissions, and the current page before acting.`;
- read-only rows: `Client`, `Target tab`, `Site origin`, `Action`, `Controller
  expires`, and applicable permission boundary;
- primary action: `Allow once`;
- safe action: `Block action`;
- initial focus and `Escape`: `Block action`;
- no raw typed value, selector, page text, script, remote rationale, or remember
  choice.

Vault use continues to invoke the Phase 20 native `Confirm Vault Use` dialog and
`Confirm and Fill` / `Do Not Fill` actions. Pairing or control never pre-approves
vault use. Privileged internal surfaces retain their current permission and
confirmation behavior; ambiguous sensitive actions fail closed.

### Destructive and safety actions

| Action | Confirmation and exact copy |
|--------|-----------------------------|
| Stop control | No confirmation. Immediately invalidate the controller lease and show `Stopping control`. |
| Cancel unused code | No confirmation. Immediately invalidate the pending code and show `Pairing code cancelled`. |
| Replace pending code | `Replace current pairing code? The current code will stop working immediately.` Actions: `Replace code`, `Keep current code`. |
| Revoke one dashboard | `Revoke access for {client}? Viewing and control for this pairing will end immediately.` Actions: `Revoke access`, `Keep paired`. |
| End all target supervision | `End supervision for {tab}? All paired dashboards will lose viewing and control immediately.` Actions: `End supervision`, `Keep access`. |

Destructive confirmations name the sanitized client or target, use destructive
color only on the committing action, put initial focus on the safe action, and
return focus to the initiating row/section heading. Repeated activation cannot
submit duplicate mutations.

## Structured Stream and Active-Action UI

The UI describes the structured stream truthfully without displaying its DOM
payload. Each viewer begins with a bounded baseline and then ordered diffs.
Navigation/document replacement or any gap produces a fresh baseline before
updates resume.

### Stream states

| Browser state | Visible label | Exact supporting copy | Available action |
|---------------|---------------|-----------------------|------------------|
| No viewers | `Not active` | `Create a pairing code to begin supervised viewing.` | `Create pairing code` |
| Baseline preparing | `Starting view` | `Prometheus is preparing a safe page snapshot.` | none |
| Live | `Live` | `Structured page updates are current.` | none |
| Navigation/new document | `Resyncing` | `The page changed. Prometheus is preparing a fresh supervised view.` | none |
| Sequence gap/overflow | `View paused for resync` | `A fresh page snapshot is required before updates continue.` | none while automatic resync runs |
| Resync failed | `Resync failed` | `Refresh supervision or end access.` | `Retry resync` |
| Restricted target | `View paused` | `This page cannot be supervised under the current permission policy.` | `End supervision` |
| Target closed | `Ended` | `The target tab closed. Dashboard access ended.` | `Choose another tab` |
| Owner/authority lost | `Ended` | `Browser authority changed. Dashboard access ended.` | `Create a new pairing code` when a new eligible target exists |

During `Resyncing` or `View paused for resync`, control remains visibly
`Paused`; no remote action may execute against the old epoch. Automatic resync
never applies a partial or best-effort diff. `Retry resync` requests a new
browser-owned baseline; it does not send an epoch or sequence from WebUI.

### Current remote action

Show at most one active action for the selected target because only one
controller exists. The panel may display:

- `No remote action active`;
- `Validating remote action`;
- `Remote action: {closed safe category}`;
- `Confirmation required in Prometheus`;
- `Verifying page change`;
- `Remote action complete`;
- `Remote action blocked`;
- `Remote action failed`.

Include safe start time and elapsed duration only. Completion and failure move
to recent audit activity; they do not retain page content. `Stop control`
remains reachable while an action is validating, executing, awaiting
confirmation, or verifying.

## Audit Activity Contract

The section ends with `Recent supervision activity`, a bounded reverse-
chronological list of browser-owned, metadata-only events. Show at most the
native configured bound; the initial UI target is 20 rows.

Allowed event labels:

- `Pairing code created`;
- `Pairing code cancelled`;
- `Pairing code expired`;
- `Dashboard paired`;
- `Viewing started`;
- `Control enabled`;
- `Remote action requested`;
- `Remote action completed`;
- `Remote action blocked`;
- `Control stopped`;
- `Access revoked`;
- `Access expired`;
- `Resync required`;
- `Resync completed`;
- `Target closed`;
- `Authority lost`.

Each row may show timestamp, sanitized client label, safe target title/canonical
origin, event category, safe action category, outcome, duration, and typed error
code. It must not show the pairing code, session/lease ID, sequence/epoch token,
IP/port, selector, DOM text, typed value, page path/query, script, prompt,
secret, vault metadata value, or remote rationale.

Empty copy is `No supervision activity yet` plus `Pairing, viewing, control,
revocation, and resync events will appear here.` The secondary action `Open
supervision logs` switches to `Logs & Diagnostics` with the `Supervision`
filter selected. It does not export or copy raw records.

## Complete State and Recovery Matrix

Every Phase 21 surface has stable loading, empty, loaded, error, and authority-
loss behavior. Browser snapshots, not elapsed renderer timers, decide terminal
state.

| Condition | Visible state | Exact recovery copy / action |
|-----------|---------------|------------------------------|
| Initial load | `Loading supervision state` | Stable skeleton rows; all mutations disabled. |
| No sessions | `No dashboards connected` | `Create a pairing code to begin view-only supervision.` |
| Generic load failure | `Prometheus could not load supervision state` | `Refresh diagnostics, then try again.` Action: `Refresh diagnostics`. |
| Service unavailable | `Supervision unavailable` | `The native supervision service is not ready. Refresh diagnostics, then try again.` |
| Private profile | `Unavailable in Private` | `Pairing and remote control are disabled in Private windows.` |
| Code already used | `Pairing code used` | `The dashboard is connected in view-only mode.` |
| Code expired | `Pairing code expired` | `Create a new code to continue.` |
| Unknown/invalid code attempt | `Pairing failed` | `Create a new code and enter it in the local dashboard before it expires.` |
| Session expired | `Dashboard access expired` | `Create a new pairing code to reconnect.` |
| Session revoked | `Access revoked` | `This dashboard can no longer view or control the tab.` |
| Controller conflict | `Control already in use` | `Control is already enabled for {client}. Stop it before choosing another controller.` |
| View-only action attempt | `Remote action blocked` | `Enable control in Prometheus before this dashboard can act.` |
| Tab owner mismatch | `Remote action blocked` | `Tab ownership changed. Review the current owner before trying again.` |
| Permission denial | `Remote action blocked` | `The current Prometheus permission policy does not allow this action.` |
| Confirmation required | `Confirmation required in Prometheus` | `Review the browser-owned confirmation to continue or block the action.` |
| Target/document changed | `View paused for resync` | `The page changed. Prometheus is preparing a fresh supervised view.` |
| Gap/backpressure | `View paused for resync` | `A fresh page snapshot is required before updates continue.` |
| Resync failure | `Resync failed` | `Refresh supervision or end access.` Actions: `Retry resync`, `End supervision`. |
| Target closed | `Target unavailable` | `The target tab closed. Dashboard access ended.` |
| Profile/window shutdown | no persisted active UI | On next launch show `No dashboards connected`; never restore a code, viewer, or controller. |

Typed error codes may appear as selectable Space Mono metadata after the human
copy. Raw backend messages must not be rendered.

## Keyboard, Focus, and Screen-Reader Contract

### Native chrome

- The tab-status cluster remains non-interactive and is skipped in keyboard
  traversal; its full state is exposed through the tab's accessible
  description and tooltip.
- Badge changes do not steal focus or announce every diff. Announce only viewer
  arrival/departure, control enable/stop, remote confirmation, and authority
  loss through the active browser surface.

### Side panel

- Focus order remains mode navigation, supervision strip, active mode content,
  then its existing actions. Within the strip: status text, `Stop control` when
  present, `End supervision`, then `Manage access`.
- `Enter` or `Space` activates the focused action. `Escape` never stops control
  or ends supervision.
- Controller/action changes use a polite live region. `Remote control enabled
  for {client}`, `Remote control stopped`, and authority loss use one assertive
  announcement because they change mutation authority.
- Refresh and tab selection changes never move focus. If `Stop control` is
  removed while focused, move focus to `Manage access` with `Remote control
  stopped` announced once.

### Control Panel

- Preserve the existing section-rail roving focus at 720px and wider; preserve
  native select behavior below 720px.
- Section focus order is: heading/status summary, target selector, pairing
  action/code actions, stream/current action, connected dashboards, recent
  access, audit activity, destructive bulk action.
- Client rows are a semantic list. Within each row the safe label/state precedes
  `Enable control` or `Stop control`, then `Revoke access`.
- On successful code creation, move focus to `Pairing code ready`, not directly
  into the code text. The code remains selectable and has an accessible label
  that reads its characters individually. It is not an automatic live-region
  announcement.
- `Copy code` retains focus and sends the copy outcome to a polite live region.
  Countdown changes are silent except at one minute, ten seconds, and expiry.
- Background viewer, timer, action, and audit refreshes preserve focus,
  selection, target choice, scroll position, and open confirmation state.
- If expiry/revocation removes the row containing focus, move focus to
  `Connected dashboards` and announce the terminal state once.
- Native `Enable control` and consequential-action dialogs expose dialog role,
  title, description, modal state, and read-only rows. Initial focus and Escape
  always choose the safe outcome specified above.
- WebUI destructive dialogs trap focus only while open, restore it to the
  invoking action, and never commit on Escape.
- Disabled competing control actions remain readable and use
  `aria-describedby` to expose the current controller-conflict copy.
- All icon-only buttons require the exact visible/tooltip command as their
  accessible name. Every status includes text. Timers use `role="timer"` but are
  not continuously live.

There are no drag-only operations. Client ordering, target selection, control
granting, revocation, copying, stopping, and resync recovery must all have
complete keyboard paths.

## Responsive and Stability Contract

The Phase 21 acceptance widths are 320px, 480px, 720px, and 1024px. No width may
produce page-shell horizontal scrolling, clipped code, overlapping status
chips, hidden stop/revoke actions, or a target label that pushes actions outside
the viewport.

### 320px

- This is the side-panel target and the minimum Control Panel content width.
- Use one column and 16px surface/section padding.
- The side-panel strip stacks status, activity, `Stop control`, and `Manage
  access`; actions are full width.
- The Control Panel uses its labeled section select, not the rail.
- Target selector, code, timer, copy/cancel actions, stream status, each client
  row, and audit rows stack in document order.
- Pairing code remains 20px and wraps never; surrounding actions move below it.
- Client labels and safe origins wrap or ellipsize with accessible full text.

### 480px

- Keep the section select and a single main column.
- Code and timer share one row only when both retain their intrinsic width;
  actions may share two equal columns, then fall back to full width.
- Client metadata uses two compact columns, while actions occupy a full row.
- Audit timestamps move above event details; no table layout is introduced.

### 720px

- Show the existing section rail plus one content pane.
- Pairing target/invariant and code presentation remain in one readable column.
- Summary metrics use two columns. Client rows show identity/state on the left
  and actions on the right, with expiry/last-seen beneath.
- Audit activity remains below connected dashboards so its growth never pushes
  current control actions off screen.

### 1024px and wider

- Keep the section rail. Inside the supervision section, use a 60/40 two-pane
  content split: target/code/stream/connected dashboards on the primary pane;
  recent access/audit activity on the secondary pane.
- `Stop control`, `Revoke access`, and expiry remain visible without opening a
  detail drawer.
- Cap long body/audit lines to a readable measure; extra width remains calm
  rather than enlarging type, icons, or cards.

Across every width, loading skeletons occupy loaded-row geometry. Theme changes,
timer ticks, viewer count changes, stream resync, controller transitions, and
error banners must not change hit-target size or move an already-focused
control. Horizontal scrolling is prohibited for the page and pairing-code
region.

## Security and Privacy UI Invariants

- A pairing code is bearer material permitted only in the intentional,
  one-time Control Panel presentation. It is absent everywhere else and cleared
  when no longer usable.
- Dashboard session/controller identifiers never enter visible WebUI state,
  accessibility text, native tooltips, logs, diagnostics, or exports.
- Pairing codes and dashboard credentials never enter prefs, browser history,
  URLs, tab titles, audit records, crash-key copy, console messages, task logs,
  MCP payloads, DOM supervision streams, or clipboard without the explicit
  `Copy code` action.
- Generic page reads and internal-surface snapshots structurally redact the
  sensitive code region. The supervision target cannot be the code surface.
- Viewer/controller UI is reconstructed from fresh native state. Renderer
  countdowns are presentational; expiry is authoritative only after the browser
  snapshot says so.
- No remote action is shown as accepted, active, complete, or verified before
  the native dispatcher returns that state. Optimistic control grant is
  prohibited.
- Active action copy is a closed category. Page text, selectors, field labels,
  typed values, scripts, and remote explanations never enter the strip, badge,
  client row, or audit list.
- View-only clients cannot issue page mutations. A controller lease does not
  weaken tab ownership, internal-surface permission, background-action policy,
  exact frame/document validation, action verification, vault confirmation, or
  profile lifecycle.
- The side panel and Control Panel discard stale snapshots whose bound native
  surface is gone. They never reacquire a different Browser/tab silently.
- No remote script, stylesheet, font, image, iframe, telemetry endpoint,
  registry dependency, QR generator, or third-party clipboard helper is
  permitted.
